Q39. Combination Sum

Description

Given an array of distinct integers candidates and a target integer target, return a list of all unique combinations of candidates where the chosen numbers sum to target. You may return the combinations in any order.

The same number may be chosen from candidates an unlimited number of times. Two combinations are unique if the frequency of at least one of the chosen numbers is different.

The test cases are generated such that the number of unique combinations that sum up to target is less than 150 combinations for the given input.

Approach

The first solution that comes to mind for a combination problem is Backtracking. Using backtracking allows us to easily explore all possible combinations by visualizing them as a decision tree, and we can prune (trim) the branches that do not meet the requirements to save time and space. So here’s how I figure out my solution: 1. first think of this as a tree, we spread out by adding one element. 2. when should we stop the recursion? 1. If the sum of the combination equals the target, we found a valid combination. We add a copy of this combination to our final result and return. 2. If adding the current element exceeds the target -> we should skip this element, try next element(because the question didn’t mention the array is sorted). 3. we only want unique combination, and we are using backtracking, it means when we tried out all combination from index 0 - n, all posssible combination that contains element[0] are tested, so in next recursion we only need to try combination from index 1 - n, in this way we avoid duplicate combination. -> we need the index from previous recursion.

Time complexity

Assume the height of the tree Target/MinElement = h. O(Nh ⋅ h)

In this question, elements can be used multiple times, so we have N options in every recursion, and the deepest depth we can go is Target / the minimum element in the array, so N * N * N … (h times), the plus one come from when we find a working combination, we need to copy it to add it to the result array.

Space complexity

Assume the height of the tree Target/MinElement = h. O(h)

We utilize one List during the whole recursion processs, and in that List, the possible maxmimum size is Target / mimimum number in the array.

Code (Java)

```Java class Solution { public List<List> combinationSum(int[] candidates, int target) { List<List> result = new ArrayList<>(); backtracking(candidates, target, 0, 0, new ArrayList(), result); return result; }

private void backtracking(int[] candidates, int target, int sum, int prevIndex, List<Integer> combination, List<List<Integer>> result) {
    if (target == sum) {
        result.add(new ArrayList<Integer>(combination));
        return;
    }

    for (int i = prevIndex; i < candidates.length; i++) {
        if (candidates[i] <= (target - sum)) {
            combination.add(candidates[i]);
            backtracking(candidates, target, sum + candidates[i], i, combination, result);
            combination.remove(combination.size() - 1);
        }
    }
}

}
